<Accordion title="Project Overview">

Letters is a full-stack application built to handle self-destructing messages. It uses a modern edge-native stack: React 19 on the frontend, Hono running on Cloudflare Workers for the backend, and Drizzle ORM with Cloudflare D1 for the database. Every design decision was made to prioritize speed, privacy, and impermanence.

</Accordion>

<Accordion title="Why I built this">

Most of what we send each other online is disposable. Hundreds of messages a day, none of them meaning much. The things that actually matter get buried in the noise.

I wanted to build the opposite. A place where you write one message to one person, share it as a single link, and know it will disappear. The impermanence is the point.

Letters started as something much smaller — a personal tool for a personal moment. But I realized early that a tool designed for one person isn't really a tool. It's a gift. And gifts are fragile. If the one person doesn't want it, the whole thing falls apart.

</Accordion>

<Accordion title="What it does">

Letters lets you write one message to one person and share it as a link. The recipient opens it, reads it, and can reply. Then it disappears.

You can customize every part of the letter — the background, the font, the message box, the buttons. Add motion effects: hearts, confetti, snow, fireworks.

Every letter lives on a progressive timer:

- **7 days** from creation
- **3.5 days** after it's been opened
- **1.75 days** after it's been replied to

<LifetimeGraph />

**Why halve the time?** It's a design choice for speed and space. Every interaction cuts the letter's life in half, forcing it to die faster. This keeps the database clean and saves storage space on Cloudflare D1.

Even if a letter is completely ignored (never opened or replied to), it doesn't matter. The original 7-day timer always runs out, meaning the space is guaranteed to be reclaimed automatically. Nothing lives forever here.

</Accordion>

<Accordion title="The hardest problem">

Letters has to render identically in two completely different environments:

**1. The live app** — React 19, Motion, Tailwind CSS, TypeScript

**2. The downloaded HTML** — plain HTML, CSS, and vanilla JavaScript

<Accordion title="Backend & Data Lifecycle">

Because letters have to self-destruct, the database needs a strict cleanup routine so it doesn't fill up with dead data. 

The system relies on two triggers:
1. **A Cron job** that runs every day at 3 AM.
2. **A User Threshold** that triggers when there are over 100 users or letters.

Whenever either of these triggers fires, it runs the exact same logic: **Normal Cleanup** always runs first, followed by a storage check. If the database is over 90% full, it runs an aggressive **Pressure Cleanup**.

<CleanupDiagram />

**Flow:** `Trigger → runCleanup() → Normal → Check 90% → Pressure`

This ensures the database stays healthy and prevents Cloudflare from hitting its storage limits.

</Accordion>

<Accordion title="Trade-offs I made">

| Decision | Why | Trade-off |
|---|---|---|
| **Cloudflare Workers** | Global edge, no servers | No full Node APIs |
| **Drizzle over Prisma** | Smaller bundle, better TS | Fewer tutorials |
| **Better Auth** | Self-hosted, free | More setup |

</Accordion>
